# zcode-session-title-patch

**Unofficial local patch for ZCode: session titles in the `category emoji + object｜goal` style, re-evaluated after every turn.**

给 ZCode 的会话标题换一套更适合"扫一眼找会话"的命名规范，并让它随着工作推进自动更新。属于非官方本地补丁（改的是应用自己的运行时文件），升级应用后会失效，重跑一次即可。

| 原来的标题 | 补丁后的标题 |
| --- | --- |
| 回应中文问候 | 🧩 邮箱验证码｜过期排查 |
| 确认注册功能 | 🧩 支付回调｜重复发货修复 |
| feature 当前进度查询 | 🧩 报价服务｜补齐进度查询 |
| 继续修改 | 🎨 登录表单｜布局优化 |

## 它改了什么

ZCode 的会话名是一次额外的模型调用生成的，那段"起名说明"写死在运行时代码里，界面没有开关。这个补丁在文件里做六处精确替换（其中"跳过规则"是插入）：

| 位置 | 原来 | 补丁后 |
| --- | --- | --- |
| 起名说明（提示词） | `Generate a concise title...`：3–7 个词，无格式约束 | 类别 emoji + 对象｜目标；含类别表、语言判定、48 字符上限、提示注入防护 |
| 触发时机 | 只在第 0 轮跑一次 | 每轮用户输入后重新评估 |
| 模型看到的材料 | 只有首条用户输入 | 原始输入、当前标题、项目名、最近 4 条用户消息 + 2 条助手消息、本次输入 |
| 跳过规则 | 无 | 手动改过名（custom）不覆盖；已有标题且本次输入 <10 字符不重新评估；还没正经标题的会话任何消息都补一次 |
| 辅助调用思考档位 | 取模型档位列表的第一个值（可能被网关拒收） | 跳过 `off`/`disabled`/`nothink`/`adaptive`/`default`/`auto`，取第一个可用档位 |

最后一条值得单独说：ZCode 用同一个函数给**所有辅助调用**（会话标题、测试连接、网页抓取后处理、项目记忆抽取）绑定思考档位，取的是"最省的那一档"。有些自建 / OpenAI 兼容网关会直接 400 拒收 `off` 这类取值，导致这些功能全部静默失败、会话标题永远停在第一句话。补丁顺手把这条修好。

## 环境要求

- 装了 [Node.js](https://nodejs.org/)（能跑 `node -v` 即可，脚本只用标准库）
- 有权限写 ZCode 安装目录（Windows 默认装在 `C:\Program Files\zcode` 或 `D:\Program Files\zcode`）
- 只在本机改文件，不需要联网、不需要任何密钥

## 快速开始

```bash
git clone https://github.com/easonlao/zcode-session-title-patch.git
cd zcode-session-title-patch

node patch.mjs --check     # 先看能不能找到 ZCode 的运行时代码
node patch.mjs             # 打补丁（自动找安装位置）
# 重启 ZCode
node status.mjs            # 自检：补丁状态 + 最近会话标题 + 最近几次起名调用
```

找不到安装位置或装在别处时显式指定：

```bash
node patch.mjs --target "/path/to/zcode/resources/glm/zcode.cjs"
node patch.mjs --revert --target "/path/to/zcode/resources/glm/zcode.cjs"
```

## 安全设计

- **按代码结构识别目标位置**，不依赖压缩后的函数名（每次发布这些名字都可能变）。有一处识别不出来就整体报错退出，不写入。
- 写入前先对结果跑 `node --check` 语法校验，校验不过不写盘。
- 打补丁时找"原厂写法"、还原时找"补丁写法"；`--revert` 用打补丁前的备份还原，实测往返后文件哈希与原始一致。
- 每次真正打补丁前都会刷新备份 `zcode.cjs.bak-titlepatch`，保证备份与应用当前版本一致，不会把旧版本文件贴回去。
- 幂等：重复执行不会重复插入（有专门的防重复插入判断）。

## ZCode 升级后

升级会替换运行时文件，补丁随之消失。三步：`node patch.mjs` → 重启 → `node status.mjs`。

脚本按代码结构找位置，小版本升级通常能直接套用。如果报「有位置匹配不上」，它会打印识别失败的环节，并保持应用为官方状态不写入。这种情况需要按新版代码结构更新 `patch.mjs` 里的 `detect()`。

`node status.mjs` 的第一行「结构识别」显示失败时，也是同样的意思：这版代码结构变了。

## 命名规范要点

- 结构：`一个类别 emoji + 空格 + 对象 + 全角「｜」+ 核心目标`，恰好一个分隔符
- 类别：🎬 内容制作 / 🧩 工具开发 / 🔎 对比调研 / 🎨 页面设计 / 📝 方法整理 / 📅 日程安排 / ⚙️ 环境配置 / 💬 一般讨论
- 长度：中文优先 10–26 个可见字符；所有标题上限 48 个 Unicode 字符
- 语言：跟随最近几轮**用户自己**表达需求的语言；助手输出、代码、日志不算证据
- 稳定：当前标题仍准确时原样返回（keep），只有工作目标实质变化才改写；格式不符时只做一次格式迁移，不许缩成最近的子问题

完整提示词见 `patch.mjs` 里的 `NEW_PROMPT`。

## 工具清单

| 文件 | 用途 |
| --- | --- |
| `patch.mjs` | 打补丁 / 还原 / 查状态（幂等，可反复执行） |
| `status.mjs` | 自检：补丁状态、最近会话标题、最近几次标题调用的档位与结果 |
| `verify-title.mjs` | 从打过补丁的文件里抽出真实的提示词与上下文构造器，用真实会话数据走一遍并**真调一次模型**（会消耗少量额度，provider 可用 `ZCODE_TITLE_TEST_PROVIDER` 指定） |
| `debug-instrument.mjs` | 排查用插桩：打印触发判断的输入、请求体里的思考档位 |

## 已知边界

- 只作用于主会话（`interactive`）：子会话、定时 / 闲时任务不参与；手动改过名的会话永远不会被覆盖。
- 标题在**本轮对话结束时**才写库，所以要看效果请在回复出现之后再看会话列表。
- 从不打开的旧会话不会被批量刷新（侧边栏靠运行时事件更新，外部改数据库不会即时反映）。
- 每次刷新是一次极短的模型调用（无工具，只带最近几轮上下文），用当前会话的模型。
